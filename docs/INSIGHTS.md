# Insights — คู่มือใช้งาน

เปิด `run.cmd`, `run_light.cmd` หรือ `run_dark.cmd` จากโฟลเดอร์โปรเจกต์หลัก แล้วเลือกไอคอนกราฟ Insights ถัดจาก Auto Optimize เปลี่ยนภาษาได้ใน Settings

แอปเริ่มติดตามทันทีและติดตามต่อเมื่อย่อไว้ใน Tray ปิดจริงด้วย Tray > Exit จึงหยุดเก็บข้อมูล การเปิดหน้า Insights ไม่ได้เปิด Auto Optimize หรือ Start with Windows ให้เอง

## ดูข้อมูล

- เลือก 15 นาที / 1 ชั่วโมง / 24 ชั่วโมง ค่าเริ่มต้น 15 นาที ส่วน 5 นาที / 30 นาที / 6 ชั่วโมงและการพักติดตามอยู่ใน “เพิ่มเติม”
- ก่อนหน้า/ถัดไปใน “เพิ่มเติม” เลื่อนช่วงเวลา; “กลับล่าสุด” กลับสู่ข้อมูลปัจจุบัน
- อันดับภาพเรียงใหม่อัตโนมัติประมาณทุก 6 วินาที แสดงสูงสุด 5 แอปที่ RAM เพิ่มขึ้นจากค่าต้น–ปลายที่วัดได้จริง แอปใหม่ขึ้นอันดับได้หลังมีข้อมูลเปรียบเทียบ พร้อมข้อความนับตั้งแต่เริ่มพบแอป ค่าที่เล็กมากแสดง KB/B
- ข้อมูลที่ข้ามการเปิดแอปใหม่หรืออ่านบางจุดไม่ได้ยังเทียบต้น–ปลายได้เมื่อทั้งสองจุดอ่านครบ กราฟคงช่องว่างไว้ แอปที่ไม่มีข้อมูลล่าสุดออกจากอันดับสด และหากเลือกดูประวัติจะระบุเวลาที่พบล่าสุด
- กดแอปเพื่อเปลี่ยนกราฟในหน้าเดียว ไม่หยุด Live เมื่อไม่มีค่าเพิ่มที่เปรียบเทียบได้ จะเลือกกราฟแอปที่ใช้ RAM สูงสุดพร้อมป้ายกำกับ
- ชื่อหลักอ่านจากคำอธิบายไฟล์โปรแกรม เช่น Google Chrome / Visual Studio Code ส่วนชื่อ .exe ยังแสดงใต้กราฟและในรายละเอียด ค้นหาได้ทั้งสองชื่อ เก็บชื่อกับประวัติในเครื่องโดยไม่บันทึกตำแหน่งไฟล์หรือคำสั่งเปิดโปรแกรม
- โปรเซสระบบที่ไม่มีตำแหน่งไฟล์ใช้ชื่อจากตารางโปรเซสของ Windows เช่น MemCompression แสดงเป็นระบบบีบอัดหน่วยความจำของ Windows ประวัติเดิมที่มีแต่ PID ระบุชื่อย้อนหลังได้เมื่อ PID และเวลาเริ่มตรงกับโปรเซสปัจจุบัน หากยืนยันไม่ได้จะระบุว่าไม่ทราบชื่อและไม่เดาชื่อจาก PID
- “ดูแอปทั้งหมด” เปิดแผงค้นหาและเรียงตามการเพิ่มขึ้น/RAM/ชื่อ เลือกแอปแล้วกลับมาดูกราฟในหน้า การค้นหาไม่เปลี่ยนอันดับภาพ
- “รายละเอียด” เปิดค่าสูงสุด กราฟ และโปรเซสที่กางดูได้ เมื่อปิดยังคงแอปที่เลือกไว้ ช่วงเวลาใต้กราฟเป็นเวลาที่อ่านแอปนั้นจริง จุดเหตุการณ์บนกราฟเลือกเฉพาะรายการที่เกี่ยวข้องกับแอปและ Optimize
- กดจุดเหตุการณ์บนกราฟหรือการ์ดเหตุการณ์เพื่อดูรายละเอียดโดยคงช่วงเวลาเดิม กด “ดูช่วงเวลานี้” เมื่อจะย้อนดูช่วงนั้น
- เหตุการณ์ล่าสุดแสดงสูงสุด 3 รายการ กด “ดูทั้งหมด” เพื่อเปิดไทม์ไลน์เต็ม
- จุดบนเมนูหมายถึงมีเหตุการณ์ยังไม่อ่าน เปิดเหตุการณ์หรือกดอ่านทั้งหมดเพื่อล้างจุด ไม่มีป็อปอัพจากเหตุการณ์ Insights
- รายการเหตุการณ์แบ่งหน้าละ 200 รายการ กราฟแสดง marker ได้สูงสุด 1,000 จุดในช่วงนั้น หากมีมากให้เลือกช่วงเวลาสั้นลง
- Escape ปิดแผงรายละเอียด คีย์บอร์ดใช้ Tab เลือกปุ่ม/แถว และลูกศรดูค่าบนกราฟได้

## ความหมายของข้อมูล

RAM รวมใช้ข้อมูลเดียวกับ Overview ทุก 2 วินาที ส่วนรายโปรเซสอ่านประมาณทุก 6 วินาทีบน worker แยก ค่าแต่ละโปรเซสเป็น WorkingSetSize ซึ่งอาจรวมหน่วยความจำที่ใช้ร่วมกัน ผลรวมรายแอปจึงไม่เท่ากับ In use ของเครื่อง

บน Windows ใช้ GetProcessTimes และ K32GetProcessMemoryInfo ด้วย PROCESS_QUERY_LIMITED_INFORMATION เพื่อลดการอ่านข้อมูลทั้งระบบซ้ำสำหรับโปรเซสที่ถูกป้องกัน โปรเซสที่สิทธิ์ไม่พอจะแสดงจำนวนที่อ่านไม่ได้ การเปิดปกติอาจอ่านบริการระบบบางรายการไม่ได้; แอปไม่ขอสิทธิ์เพิ่มอัตโนมัติ

อ่าน API: [GetProcessMemoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessmemoryinfo), [GetProcessTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes), [Working Set](https://learn.microsoft.com/en-us/windows/win32/memory/working-set)

ชื่อโปรแกรมใช้ FileDescription / ProductName จาก [VerQueryValueW](https://learn.microsoft.com/en-us/windows/win32/api/winver/nf-winver-verqueryvaluew) และทำงานบน worker พร้อมแคชตามตำแหน่งไฟล์ ไม่เปลี่ยนการจัดกลุ่มโปรเซสหรือวิธีวัด RAM

ตัวเลข RAM ที่เพิ่มขึ้นเป็นการเปลี่ยนแปลงที่วัดได้ ไม่ได้ยืนยันว่าเป็น memory leak หรือเป็นสาเหตุที่ทำให้เครื่องช้า แอปที่เพิ่งเปิด/ปิดและช่วงข้อมูลไม่ครบมีสถานะแยก

ประวัติ 30 นาทีล่าสุดเก็บละเอียด ส่วนที่เก่ากว่าสรุปเป็นหนึ่งนาทีพร้อมเก็บค่าสูงสุด/ต่ำสุด Tooltip ของข้อมูลสรุปแสดงว่าเป็นรายหนึ่งนาที ไม่อ้างว่า peak เกิดตรงวินาทีที่วาดจุดไว้ การเลือกเวลาย้อนหลังใช้เฉพาะ bucket ที่อยู่ครบในช่วง เพื่อไม่ดึงข้อมูลอนาคตเข้ามา

กราฟเว้นช่วงเมื่อปิดแอป, พักติดตาม, Sleep หรืออ่านข้อมูลไม่ได้ รุ่นนี้ไม่มีบริการที่ทำงานต่อหลัง Exit และไม่เติมข้อมูลในช่วงที่แอปไม่ได้ทำงาน

## การเก็บประวัติ

เก็บที่ %LOCALAPPDATA%\ThrashingMitigatorRedesign\insights\insights.db พร้อมไฟล์ journal ของ SQLite อายุประวัติ 24 ชั่วโมง โดยเก็บเฉพาะช่วงที่แอปทำงานจริง ข้อมูลประวัติไม่ได้อยู่ใน ZIP หรือโฟลเดอร์ portable และไม่ได้ส่งขึ้น cloud

บันทึกเป็น batch ประมาณทุก 30 วินาที และ flush เมื่อ Exit ปกติ การปิดผิดปกติอาจเสีย batch ล่าสุด เมื่อฐานข้อมูลอ่านไม่ได้ แอปเก็บไฟล์เสียเป็น .corrupt-* ก่อนเริ่มไฟล์ใหม่

หากบันทึกไม่ได้ ระบบยังติดตามสดในประวัติชั่วคราวล่าสุดประมาณ 30 นาที พร้อมแสดงข้อผิดพลาด กด Settings > ข้อมูลการวิเคราะห์ RAM > ลองบันทึกอีกครั้ง เพื่อรวมข้อมูลชั่วคราวกับประวัติเดิม เมื่อแก้ปัญหาพื้นที่/สิทธิ์แล้ว

ล้างประวัติได้ใน Settings โดยมีการยืนยัน ปุ่มนี้ล้างทั้งประวัติที่บันทึกและข้อมูลชั่วคราว ไม่เปลี่ยนการตั้งค่า Auto, ภาษา หรือธีม
